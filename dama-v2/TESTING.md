# 담아 v2 테스트 운영 기준

## 목적

사용자 휴대폰을 반복적인 개발 테스트 장비로 사용하지 않는다. 기능 변경은 통제된 자동 테스트에서 먼저 검증하고, 실제 기기 설치는 모든 자동 게이트를 통과한 단일 후보판에서만 수행한다.

## 자동 테스트 계층

### 1. 순수 로직 테스트

- URL 정규화와 브라우저 fragment 제거
- 직접 MP4, HLS, DASH 분류
- 추출기 체인과 명시적 실패코드
- 403, 429, 로그인, 쿠키, 연결 초기화 분류
- 연결 초기화에 한해 기본 연결 1회와 IPv4 1회만 실행
- 일반 오류에는 불필요한 재시도를 하지 않음

### 2. 통제된 네트워크 통합 테스트

`test-harness/fixture_server.py`가 외부 사이트와 무관하게 다음 상황을 항상 동일하게 재현한다.

- HTML 안의 직접 MP4
- HLS manifest와 segment
- DASH manifest
- HTTP 403
- HTTP 429
- 쿠키 필요
- 로그인 안내 페이지
- TCP connection reset

호스트용 yt-dlp가 fixture HTML에서 직접 MP4를 찾는지까지 확인한다.

### 3. Android 빌드 게이트

아래 순서가 모두 성공해야 APK artifact를 생성한다.

1. 통제된 네트워크 통합 테스트
2. Kotlin 단위 테스트
3. Android lint
4. debug APK 빌드

하나라도 실패하면 설치 후보 APK를 배포하지 않는다.

## 실제 기기 테스트 원칙

- 자동 테스트로 재현할 수 없는 Android 네이티브 동작만 확인한다.
- 여러 수정마다 새 APK를 설치하지 않는다.
- 한 개발 주기의 변경을 모아 단일 후보판으로 확인한다.
- 실제 사이트 테스트는 직접 MP4, 일반 페이지, 쿠키 필요, 브라우저 폴백의 대표 URL만 사용한다.
- 실패 시 화면 캡처만 요구하지 않고 앱 내부 진단 로그를 먼저 확보하도록 개발한다.

## APK 배포 게이트

다음 조건을 모두 충족하기 전에는 사용자에게 새 APK를 전달하지 않는다.

- CI 전체 성공
- 테스트 보고서 생성
- 변경 범위와 미검증 범위 명시
- 기존 후보판보다 확인 가능한 개선점이 있음
- 단순 오류 문구 변경이나 추측성 옵션 조정만으로는 배포하지 않음
