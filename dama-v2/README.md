# 담아 v2

기존 v1 패치 체인을 재사용하지 않는 새 코드베이스입니다.

## 목표

URL 입력 또는 Android 공유로 받은 주소를 다음 고정 파이프라인으로 처리합니다.

`입력 검증 → 추출기 체인 → MediaDescriptor → 다운로드 엔진 → 저장 → 결과 검증`

## 민감도 선행분석

| 결정 | 영향도 | 리워크 위험 | v2 결정 |
|---|---:|---:|---|
| 추출 엔진 경계 | 5 | 5 | `MediaExtractor` 인터페이스 뒤로 격리 |
| 공통 미디어 모델 | 5 | 5 | `MediaDescriptor`를 모든 엔진의 유일한 출력으로 고정 |
| 패키지·서명 | 5 | 5 | 개발 중 `com.sajang.dama.next`, 검증 후 정식 패키지 전환 |
| 브라우저 폴백 | 5 | 5 | Core에 포함하지 않고 별도 어댑터/프로세스로 제한 |
| 실패코드 | 4 | 5 | 단계와 원인을 enum으로 고정, `UNKNOWN` 남용 금지 |
| 다운로드 구현 | 4 | 4 | 추출기와 분리된 `DownloadEngine` 계약 사용 |
| 저장 위치 | 3 | 3 | MediaStore 기반, 세부 설정은 이후 |
| 화면 디자인 | 2 | 2 | 기능 검증 뒤 조정 |

## 과잉코드 방지 원칙

- 단일 앱 모듈로 시작한다. 실제 구현체가 2개 이상 생기기 전에는 모듈을 나누지 않는다.
- 사이트 이름을 조건문에 직접 넣지 않는다.
- 추출기·다운로더·UI가 서로의 구현 세부사항을 알지 못하게 한다.
- 오류를 삼키지 않는다. 실패 단계, 코드, 기술 상세를 보존한다.
- DRM·암호화·로그인·결제 제한을 우회하지 않는다.
- 사용되지 않는 설정 화면, 데이터베이스, 캐시 계층은 만들지 않는다.

## 첫 번째 수직 기능

현재 첫 커밋은 직접 미디어 URL만 처리합니다.

- MP4/WebM/MOV/M4V
- HLS M3U8
- DASH MPD
- Android 공유 수신
- 단계별 상태와 명시적 실패코드

이 수직 기능이 빌드·테스트를 통과한 다음 `yt-dlp` 어댑터를 같은 `MediaExtractor` 인터페이스에 추가합니다.
